## What these examples contain

Each standard preset includes its core services and default selections, with the usual image channels, comments, paths, ports, and environment variables. The `custom` example selects Privateerr, Gluetun with automatic recovery enabled, qBittorrent, Prowlarr, Radarr, Sonarr, and Sonarr Anime. Required dependencies are included automatically. This example does not change the empty starting selection of the interactive custom preset.

These are source-revision references, not a promise that the current stable `latest` generator has identical output. They are validated without starting application containers and omit deployment `.env` files, generated credentials, and all config seeds. Copying the public pair alone does not prepare required bind sources, application configuration, or private keys. Use [the setup instructions](../../docs/setup.md) and `make configure` to prepare a deployment with its own secrets and configuration, then review credentials and host paths before launch.

To reproduce the curated custom selection with your own generated secrets and configuration, first build the local image as described below, then run this from the repository root:

```sh
make ship MARAUDARR_IMAGE=maraudarr:examples PRESET=custom ADD_SERVICES=privateerr,gluetun,qbittorrent,prowlarr,radarr,sonarr,sonarr-anime
```

The interactive custom preset still starts with no services checked. An empty non-interactive custom selection is rejected; select services explicitly rather than treating the curated example as a default. Review the resulting `dist/custom/.env` before starting any containers.

## Refresh the references

Build the production Maraudarr image from this checkout and regenerate every example:

```sh
make build examples MARAUDARR_IMAGE=maraudarr:examples MARAUDARR_BUILD_OPTIONS=--pull
```

Verify the checked-in references against fresh container output:

```sh
make test-examples MARAUDARR_IMAGE=maraudarr:examples
```

Generation runs twice in disposable directories and requires byte-identical public output. Only `docker-compose.yml` and the secret-free `example.env` are copied here; deployment `.env` files and config state stay private.

Pull requests validate and refresh these examples together with the source changes. For branches in this repository, a separate job commits changed references and dispatches fresh validation and CodeQL checks. Fork contributors can download the `preset-examples` workflow artifact or regenerate locally and commit the pairs. Main-branch publication verifies the merged examples without writing another commit.
