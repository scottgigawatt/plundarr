# Velvarr service chart 🔞

Adds the [Velvarr adult-media discovery and request application](https://github.com/Skare69/velvarr) as a removable Boudoirr default. Both CLI generation and Maraudarr's interactive picker select it initially; use `REMOVE_SERVICES=velvarr` or clear its checkbox to omit it. Jellyfin is also a removable Boudoirr default; use `REMOVE_SERVICES=jellyfin` when connecting an existing server. Other presets can add either companion explicitly. Whisparr and Jellyfin are recommended integrations rather than forced container dependencies: either can run in another project or on another host. Jellyfin is required to complete Velvarr's owner setup and authenticate users; Whisparr v3 fulfills approved requests.

The chart defaults to `VELVARR_IMAGE=ghcr.io/skare69/velvarr` and `VELVARR_TAG=latest` in both generated environment files and uses the shared host UID/GID mapping, a read-only root filesystem, and a writable `/data` bind mount. The default official image currently supports `linux/amd64` only. The Node.js public healthcheck follows [upstream's Dockerfile](https://github.com/Skare69/velvarr/blob/main/Dockerfile), with Plundarr's shared timing settings. Upstream's [Compose example](https://github.com/Skare69/velvarr/blob/main/compose.yaml) does not enable a read-only root filesystem; that is Plundarr hardening, with persistent `/data` and temporary `/tmp` remaining writable. No `depends_on` entries are needed because integrations are configured after startup and can run externally. Velvarr is eligible for Watchtower updates.

Set `VELVARR_IMAGE` to an image repository without a tag and `VELVARR_TAG` to its channel or version in the generated `.env` to use a fork. The Compose chart keeps both references unresolved, and regeneration preserves your overrides. See [image selection](../../../docs/project-guides/velvarr.md#select-the-image) for the update commands.

Maraudarr generates both required secrets once and preserves existing assignments. Homepage receives a link card only when both services are selected. See the [Velvarr setup guide](../../../docs/project-guides/velvarr.md) for connection URLs, permissions, backups, and recovery.

The database uses the host bind mount rather than named volumes or separate database containers. Stop Velvarr before copying its complete data directory and retain the matching `VELVARR_SECRET_KEY` separately. For browser origin, use the address you open, such as `http://192.168.1.210:16699` on the LAN or `https://velvarr.example.com` behind a reverse proxy, without a path or trailing slash.

The `/tmp` tmpfs provides disposable writable scratch space alongside the read-only root filesystem. Its `64m` limit caps that filesystem at 64 MiB; it does not limit total application memory. This is a Plundarr allowance, not an upstream sizing recommendation. The database stays in `/data`, and [upstream artwork caching](https://github.com/Skare69/velvarr/blob/main/src/server/providers.ts) uses application memory rather than `/tmp`. Startup, database, and restart checks pass with this cap, but they do not establish a production peak. Inspect actual usage with `docker compose --project-directory dist/boudoirr exec velvarr df -h /tmp` when assessing a larger allowance.
