# Velvarr service chart 🔞

Adds the [Velvarr adult-media discovery and request application](https://github.com/Skare69/velvarr) as a removable Boudoirr default. Both CLI generation and Maraudarr's interactive picker select it initially; use `REMOVE_SERVICES=velvarr` or clear its checkbox to omit it. Other presets can add it explicitly. Whisparr and Jellyfin are recommended integrations rather than forced container dependencies: either can run in another project or on another host. Jellyfin is required to complete Velvarr's owner setup and authenticate users; Whisparr v3 fulfills approved requests.

The chart uses the official floating `latest` channel, the shared host UID/GID mapping, a read-only root filesystem, and a writable `/data` bind mount. The image currently supports `linux/amd64` only. The Node.js public healthcheck follows [upstream's Dockerfile](https://github.com/Skare69/velvarr/blob/main/Dockerfile), with Plundarr's shared timing settings. Upstream's [Compose example](https://github.com/Skare69/velvarr/blob/main/compose.yaml) does not enable a read-only root filesystem; that is Plundarr hardening, with persistent `/data` and temporary `/tmp` remaining writable. No `depends_on` entries are needed because integrations are configured after startup and can run externally. Velvarr is eligible for Watchtower updates.

Maraudarr generates both required secrets once and preserves existing assignments. Homepage receives a link card only when both services are selected. See the [Velvarr setup guide](../../../docs/project-guides/velvarr.md) for connection URLs, permissions, backups, and recovery.

The database uses the host bind mount rather than named volumes or separate database containers. Stop Velvarr before copying its complete data directory and retain the matching `VELVARR_SECRET_KEY` separately. For browser origin, use the address you open, such as `http://192.168.1.210:16699` on the LAN or `https://velvarr.example.com` behind a reverse proxy, without a path or trailing slash.
