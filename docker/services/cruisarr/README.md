# Cruisarr service chart 🔞

Adds the private [Cruisarr discovery and request application](https://github.com/scottgigawatt/cruisarr) as a removable Boudoirr default. Both CLI generation and Maraudarr's interactive picker select it initially; use `REMOVE_SERVICES=cruisarr` or clear its checkbox to omit it. Jellyfin is also removable. Other presets can add either companion explicitly. Whisparr and Jellyfin are recommended integrations rather than forced container dependencies: either can run in another project or on another host. Jellyfin provides owner setup and user authentication; Whisparr v3 fulfills approved requests. Cruisarr supports TPDB and TMDB movies, StashDB scenes, and multiple Whisparr connections.

The chart defaults to `CRUISARR_IMAGE=ghcr.io/scottgigawatt/cruisarr` and `CRUISARR_TAG=latest`. The private package supports `linux/amd64` and `linux/arm64`, not ARMv7. Authenticate the deployment host to GHCR with package-read access before pulling. No registry token belongs in the generated environment. Cruisarr is excluded from Watchtower updates; use an authenticated manual pull and recreation. Release checks default to disabled because the repository is private. See [authentication and image selection](../../../docs/project-guides/cruisarr.md#authenticate-and-select-the-image).

Plundarr overrides the image's UID/GID 10001 with the shared host UID/GID mapping. The image's application files are readable by that identity; ensure the `/data` bind mount is writable by `DEFAULT_PUID:DEFAULT_PGID`. Plundarr adds a read-only root filesystem, dropped capabilities, and no-new-privileges. The `/tmp` tmpfs allows up to 64 MiB of disposable scratch space; this is a Plundarr allowance, not an upstream memory-sizing recommendation. The persistent database is `cruisarr.sqlite` under `/data`. No media mounts, named volumes, or separate database containers are needed.

The Node.js `/api/status` healthcheck follows [Cruisarr's Dockerfile](https://github.com/scottgigawatt/cruisarr/blob/main/Dockerfile) with shared Plundarr timing. It checks storage readiness without requiring completed owner setup. Health does not prove that sign-in or provider connections work. No `depends_on` entries are needed because integrations are configured after startup and can run externally.

Maraudarr generates both required secrets once and preserves existing assignments. Keep `CRUISARR_SECRET_KEY` with off-host backups and read `CRUISARR_SETUP_SECRET` locally for initial setup. Homepage receives a link card only when both services are selected. See the [Cruisarr setup guide](../../../docs/project-guides/cruisarr.md) for connection URLs, permissions, backups, and recovery.
